# 暂存箱

功能始于开发构建 303，本文包含当前开发版 1.0.0（349）的使用方式，以及拖动取消问题的历史排查和桌面反馈。

拖动本机文件、文件夹、图片、文字或网页链接时，在鼠标所在显示屏靠近的一侧出现暂存箱。307 起收敛为 156 × 360 点的单列缩略图列表，小屏按可用高度缩减；图标为 64 点，文件名单行放在图标下方，长名称截断并可悬停查看。所有项目都在列表内，上下滚动查看。拖入添加，拖入成功后保持在原位置显示；重复拖入或后续取消拖动不收起。移除最后一项或清空后自动隐藏，下一次拖动可再次唤起空投放区。普通窗口移动、尺寸调整、截图选区和面板内排序不触发。

- 列表内可单项拖动、⌘ 点击多选、Shift 连选，或按 ⌘A 全选（不再显示全选按钮）；拖动标题可将全部内容一起拖出。按 Esc 由系统取消当前拖动。310 版的临时全局 Esc 绑定和按键转发实测未解决问题，并影响剪贴板取消，311 已撤回。仅被动观察 Esc，保留物理按键由系统处理，不预留 Esc 快捷键、不重新构造按键、不新增输入权限。312 起明确区分“观察到取消请求”和“系统确认取消”：观察器不改写正在进行的会话操作；系统最终报告取消或拒收则保留项目，报告成功则移除实际拖出的项目，即使之前观察到 Esc，也不能留下已投放的项目。不会删除原文件。313 起点击暂存项时使用正常激活的浮窗取得键盘焦点；自动显示只调用置前显示，不主动激活应用。拖出过程中源窗口一直保持原位置、正常透明度和输入状态，不再将不激活的源窗口延迟移出所有显示屏，避免跟踪期间改变键盘焦点所在窗口的可见范围。重复结束回调不会再次收尾。314 起 macOS 27+ 由实际命中的文件行或标题上的鼠标拖动手势发起系统手势会话；同一手势不会被父背景重复发起，子按钮不参与拖动。Esc 被应用收到时，禁用当前活动手势以请求实际取消，并继续交还原始按键。会话和源视图保留到系统结束回调；不因手势进入取消状态就提前清空、关闭面板或伪造投放失败。旧系统仍使用原生鼠标事件接口。315 起暂存箱与剪贴板统一为完整的鼠标专用手势：按下、阈值移动和松开都由同一识别器处理，拖动源视图不再重载 mouseDown/Dragged/Up，以免仍进入旧跟踪兼容路径。macOS 27+ 使用这个识别器交接原生拖放，交接过程中不强制激活应用或切换键盘焦点；旧系统使用缓存的原始鼠标按下事件。
- 选中后按空格预览；多选时显示最后点击的项目。复用剪贴板的气泡预览：图片支持适合窗口、100% 与捏合缩放，文字与链接使用相同的文本渲染，其他文件继续交给系统 Quick Look，不自动访问链接。再次按空格或 Esc 先关闭预览，保留非空暂存箱；预览打开时改变选择会同步更新内容。移除预览项或清空时关闭相应预览，原文件的安全作用域访问权持续到渲染器释放。
- 单项叉号仅在鼠标悬停对应文件时显示；已有缩略图、文件名和空白区域都能接收新的投放。
- 截图时保留已显示的暂存箱及预览，暂时降低层级以避开截图遮罩；完成、取消或失败后恢复，不清空内容、不移动窗口。
- 在暂存箱上两指向屏幕侧边横滑收起，保留 18×84 点的可点击标签；点击恢复原位置、滚动和选择。竖向浏览或反向滑动不收起；有效内容拖到标签时也会展开接收。309 起收起与展开使用约 0.28 秒的侧移淡入淡出：完整列表保持原尺寸，仅在完全透明时切换为标签布局，避免挤压文件。连续反向操作接续当前画面；系统“减少动态效果”开启时取消侧移、缩短为 0.12 秒淡入淡出。有效拖入立即结束过渡并稳定为完整接收区；开始截图或其他内容操作前结束动画，隐藏、清空和重新唤起时取消旧回调。
- 空格预览共用剪贴板的保存图片、OCR、翻译、标注、钉住及快捷键，文字和链接可编辑，并保留文本处理功能。仅保存副本、移除副本和重新关联等历史专属动作隐藏。OCR 状态属于当前预览，取消和失败都会结束加载；查看或识别不会自动导入历史。显式复制识别/译文及保存标注结果沿用剪贴板的写入历史规则。
- 成功拖出图片后，内部文件保留约一分钟供目标异步读取，然后自动回收；异常退出后，下次启动会回收过期的无引用内部图片。文件访问权同样短暂保留以支持目标读取；不复制大文件。
- 图片、PDF 和视频文件按需异步请求系统缩略图，生成失败时保留文件图标。独立图片使用缩略尺寸显示、原图预览；缩略图仅在内存缓存，不额外存储原文件副本。
- 原文件仅保存位置引用和可获得的安全作用域书签，不读取并保存整份文件副本。应用持续保留本次投放授予的访问权。重启后尝试恢复书签；文件失效时保留记录并说明原因，不替用户搜索同名文件。
- 从剪贴板历史拖入的独立图片另存于暂存箱，避免原历史到期后失效；其他图片格式数据规范为 PNG。普通图片文件与其他文件一样保存位置引用。文字和链接按原值保存。
- 暂存内容在本机独立保留，拖入和预览不新增历史、不修改系统通用剪贴板、不上传。预览中的复制按钮仅在用户点击时将内容写入系统剪贴板；移除仅作用于暂存项，不操作原文件。取出对原文件仍是复制；系统报告目标接受投放后仅移除对应暂存项，取消或拒收保留，取出最后一项后隐藏空箱。关闭浮层或重启应用不清空；单项移除和确认清空仅移除暂存。
- 上限 100 项，独立图片及文字合计 128 MB，单图 32 MB / 4000 万像素，单段文字 2 MB。超限不自动淘汰。整批投放失败时保留原清单并回收本批新图片，不部分提交。
- 菜单栏可手动打开；设置 → 通用 → 暂存箱，可关闭拖动时自动显示。关闭自动出现不影响手动使用或已保存内容。
- 新系统用原生玻璃，macOS 14–15 使用原生磨砂。位置避开菜单栏和 Dock，并支持外接屏、负坐标屏幕和全屏空间。

自动出现优先根据拖放剪贴板的新格式触发，补充鼠标拖动事件与低频按键状态检查，以兼容 Dock 下载栈可能吞掉鼠标按下事件的路径。仅按住鼠标且尚未识别拖动时，最多每秒四次检查鼠标附近是否存在系统拖动图像窗口；只使用窗口层级、边界与透明度元数据，不截图或读取窗口标题。空闲检查只看鼠标按钮状态，关闭自动出现会停用检查。

实际投放始终读取 AppKit 交付的拖放剪贴板，兼容原生文件 URL 及旧文件名列表格式；不依赖自动检测使用的公开拖放剪贴板。仅提供专属格式或延迟文件承诺的源应用仍需先保存为本机文件。无需为自动显示额外申请辅助功能或屏幕录制权限。Dock 下载栈和多屏实际手势由用户在测试版验证。

## 316 拖动偏移与系统状态对照（2026-11-12）

315 的真实失败日志确认：进入系统 willBegin 回调之前，输入识别器已从 changed 重置到 possible，缓存的鼠标事件也已清空。因此，314/315 的“禁用活动手势”并没有实际取消原生拖放，早先只保持手势活动的回调夹具不足以覆盖这个状态。316 撤回这项无效调用，仍以原生 ended 操作为最终结果，补充识别器已重置后收到 Esc 的隔离回归，不再把识别器状态测试称作真实系统取消通过。

独立 AppKit 对照分别测试原始鼠标事件、当前拖动事件、系统手势和自定义手势；关闭开发版后仍复现。macOS 26.5 SDK 对照也复现。系统只读记录确认 Esc 物理按下和松开均到达 HID，鼠标左键仍按住；只观察 Esc，未记录其他按键。随后系统 NSTableView 内置拖动与访达同样不能取消。关闭所有临时对照程序并重启 Dock 后，用户确认访达恢复，重新打开原有 315 版后，剪贴板与暂存箱均能立即取消。这确认当时存在应用之外的拖放状态异常，尚不能证明其触发原因或长期稳定性；应用不会自行重启系统进程、模拟系统按键或增加权限。

另修复卡片缩略图偏移：手势接口从鼠标离开面板时才开始，预览帧必须以当前手势位置为中心；复用初次按下位置会产生整段移动距离的偏差。旧系统事件接口继续按其起始事件对齐。软件回归检查两条坐标路径；316 的实际多屏位置、目标应用投放和连续取消仍由用户确认。

316 桌面反馈更新：用户确认缩略图已经贴近鼠标，但剪贴板与暂存箱的 Esc 再次失效。在不退出当前 316 进程的情况下单独重启 Dock，用户反馈“先正常，随后又失效”。因此 Dock 重启只能作为本轮诊断中的暂时恢复，不能当作应用修复或长期验收结论。随后退出开发版，仅保留系统 NSTableView 对照，用户反馈只有第一次取消成功、访达正常；这段对照期间不运行其他输入测试，避免混入额外变量。

## 316 后续桌面确认：QQ 闪传悬浮窗干扰（2026-11-12）

复核发现此前的原生对照也在拖动开始时关闭了取消回弹动画，不能将它称为完全默认的系统行为。新增保留系统默认动画的临时对照，不改应用源代码。用户随后反馈：退出 QQ 后，四种对照均能正常取消，并指出 QQ 的“拖拽文件时打开闪传悬浮窗”功能可能参与了干扰；接着明确确认原有 316 版本也正常。因此暂停修改应用的取消逻辑，继续保留 316 的拖动实现及已确认的缩略图定位修复，不因这次排查发布新的应用构建。

目前证据明显指向 QQ 拖动悬浮窗与系统拖放取消之间的交互，不能再把该现象归因于旧开发进程，也不能将重启 Dock 或更改取消动画称为已验证的根因修复。已经确认的是退出 QQ 后原有 316 恢复；重新开启 QQ、仅关闭该功能后的连续取消尚未验证。应用不自动退出 QQ、修改其设置或重启 Dock。临时检查程序在本轮结束时退出，保留用户当前运行的 316 开发版。
