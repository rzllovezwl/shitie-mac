# 阶段 2：富文本与文件记录

阶段 2 在测试版构建号 15 开始实现。已提审的商店构建号 4 保持原样。

## 保存和再次复制

- 纯文本按原始 UTF-8 内容保存。缩进、制表符、换行及结尾空行不会在存储和回写剪贴板时被整理。
- 如果剪贴板同时提供文字与 RTF、HTML 或 RTFD，记录会分别保存这些原始表示。再次复制时会同时写回纯文本与可用的富文本表示，由目标应用决定采用哪一种。超过 15 MB 的富文本表示不保存，但仍尝试保存符合 1 MB 限制的纯文本。
- Finder 等应用复制的本机文件默认只保存**原位置引用**、文件名、类型、大小与预览缩略图。引用本身不等于文件副本；原文件移动、删除或权限失效后，如果没有副本，该记录不能再次复制文件。
- 在文件详情点击“保存副本…”后，应用才会将文件内容复制到自己的 `FileCopies` 目录。以后再次复制该记录会优先使用这份副本。副本是当时的快照，不随原文件变化而更新；可点击“更新副本…”重新保存。原位置失效时，更新副本需要用户重新选择文件。界面会分别显示原位置和副本文件名。
- 文件记录删除或过期时只删除应用保存的引用、缩略图和副本，不删除原文件。清空历史也不会清空当前系统剪贴板。

## 数据兼容性与空间

现有 SQLite 数据库从版本 1 增加可空列并升级到版本 2，旧记录保持可读。文本、富文本、图片、文件书签、副本和缩略图各自放在数据目录的独立子目录；所有活跃目录的实际占用计入历史存储上限。未关联的内容会移入 `UnreferencedRecovery`，需用户明确操作才删除。旧 JSON 迁移备份仍单独保留。

相同文字但格式不同会保留为不同记录；相同文字与相同富文本表示再次复制时，会合并为一条并更新最近复制时间与次数。同一原文件位置再次复制也会合并。文件位置引用不自动更新已保存的副本。

## 测试边界

`Tests/Stage2Smoke.swift` 使用独立临时目录和独立剪贴板，检查富文本原始字节与代码空白字符回写、重复内容合并、重启后恢复、文件位置与副本的区分、原文件删除后的副本可用性、失效引用的失败返回、旧数据库升级。Xcode 构建还运行版本记录检查。

这些代码测试不验证 macOS 沙盒下 Finder 文件书签的实际授权，也不验证目标应用最终采用哪种富文本表示、来源应用图标的视觉效果以及菜单栏图标的实际尺寸。测试版需要人工检查这些桌面交互；未来商店构建还需单独验证沙盒版本。
