# 阶段 0：历史记录基础

测试版：ClipHoook 1.0.0（14）。已提审的构建号 4 不在本次更新范围内。

## 数据结构

- `history.sqlite`：记录 ID、类型、去重摘要、首次与最近复制时间、已知复制次数、来源应用名称与 Bundle ID、内容文件名和字节数。
- `Content/<ID>.txt`：UTF-8 原文，保留缩进、换行和空白。SQLite 不存剪贴板正文。
- `Images/<ID>.png|tiff`：图片原始数据。
- `LegacyMigrationBackup`：迁移前的完整 `history.json` 和其引用的图片。独立保留，直到用户在设置中确认删除。
- `UnreferencedRecovery`：数据库未关联的内容文件。应用会移入此处，不直接删除；用户可在设置中检查占用并确认删除。

旧 JSON 中没有首次复制时间、复制次数或来源 Bundle ID；这些字段保持未知。新记录从首次捕获开始计数，重复复制只更新同一条记录的最近复制时间和来源。旧记录再次复制时，也不会猜测历史总次数。

## 迁移与回退

首次启动时，先校验旧 JSON 和图片，再备份，随后将文字原样写入内容文件并导入临时数据库。逐条校验 ID 和正文后，才启用新数据库并移走旧索引。任一步失败会保留旧索引和图片，并停止写入。若新数据库与根目录的旧 `history.json` 同时出现，应用会停止写入，避免旧版和新版各写一份历史。

如需手动回退：退出所有 ClipHoook 进程；另行复制整个应用数据目录；从 `LegacyMigrationBackup` 把 `history.json` 和 `Images` 还原至数据目录，移走当前 `history.sqlite` 与 `Content`，再运行旧版。不要一边运行旧版一边运行构建 14。

## 存储与隐私

保存时间按最近复制时间计算。存储上限按当前 SQLite 数据库、文字文件和图片文件在磁盘上的分配大小计算；超出时删除最早记录。备份与恢复目录单独显示占用，不计入当前历史上限。单条删除和清空历史都不会清空系统剪贴板，也不会隐式删除迁移备份或恢复目录。

应用排除基于轮询时的前台应用推断。切换应用期间，如已配置排除应用，来源不明确的内容会跳过；后台应用主动写入剪贴板时无法保证准确识别其来源。若排除设置损坏，应用停止保存新记录。诊断日志不写剪贴板正文。

## 验证

`Tests/StorageSmoke.swift` 使用独立临时目录，覆盖代码格式、去重元数据、重启恢复、文本和图片单条删除、旧数据迁移及备份、失败回退、双写检测、空间和时间清理、恢复目录、应用排除。Xcode 测试版 Debug 构建与签名检查另行执行；面板交互由用户在自己的 Mac 上验证。
